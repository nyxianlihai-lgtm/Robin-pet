2026-10-29 本地调整：取消独立“转身再回来”入口及触发；对已识别的旧帧序，招呼缩短至约 3.2 秒，走路循环改用源视频跳变前的完整步态区间。此为旧素材的局部修正，转向与步态衔接仍需新视频；制作提示词见 [WALK_VIDEO_PROMPTS.md](WALK_VIDEO_PROMPTS.md)。原 PNG 与素材清理结果保持不变。

随后本地接入用户新提供的完整散步视频：289 帧、24fps，整段固定缩放与脚底锚点，保护绿色眼睛并清理外轮廓。分为连续的起步 0–71 帧、行走 72–215 帧、收步 216–288 帧；三段严格按原视频顺序连接，中间行走设置 `cycles: 1`，不循环或倒放。旧 PNG 保留，只有三段散步的播放索引被替换；启用前保留完整本地备份。其余动作与素材保持原状。新素材存在的绘制变化、运动模糊仍取决于源视频质量。

新增可选的 `shy`（害羞回应）、`sing`（唱歌）与 `stretch`（困困伸懒腰）动作，按用户自备视频正向播放一次后返回待机。制作阶段使用被忽略的 `data/pet-assets/`；v1.2 将实际使用的动作帧整理到 assets/video2_hq/ 随附，原始视频、参考图、备份和个人配置仍不分发。

伸懒腰片段保留源视频的 289 帧、24fps（约 12 秒），使用整段固定的缩放与脚底锚点，保护绿色虹膜后进行外轮廓清理。通过菜单或独立预览的 `7` 键触发，播放一次后返回待机；连续待机 30 秒后，该动作可参与随机选择。加入前的完整本地帧包保留备份。

唱歌片段通过独立画布偏移与透明留白容纳两侧音符，保持原有人物大小。眼睛保护按源分辨率判断绿色虹膜，避免固定面积上限导致误抠；切换过渡使用预乘透明度的加权混合，修正叠加混合造成的发白。当前播放的是动作帧，不播放源视频音轨。制作方法来源见下文。

本地帧包还进行了外轮廓去杂边：仅处理人物外侧的窄边界带，使用邻近不透明前景颜色清理浅灰残留，并轻微收紧半透明边缘；人物内部与动作时序保持不变。处理前的完整帧包保存在本地备份中。缩放前显式转换为预乘透明度格式，避免透明像素的颜色参与轮廓插值。

## 上游流程中值得采用的部分

上游把制作拆成动作配方、透明素材处理、播放器接入三个阶段。其教程要求生成视频固定镜头、构图与角色比例，动作完成后回到统一站姿；移动表现使用原地步态，实际桌面位移交给程序。

文档说明原参考素材的 106 个动作采用 PR 手工抠像，HSV 自动抠像作为兜底。处理中先统一站立高度与脚底锚点，再制作透明播放文件。因此，精细抠像是质量流程的一部分，不能期待仅靠播放器消除源素材中的绿边和误抠。

教程使用 2160×1215 中间画布，再输出 640×360、24fps 的透明 VP9 WebM。播放器几何约定为脚底 y=330。这些是上游自身规格；Robin-pet 应保留适合自身显示尺寸和 DPI 的清晰度，无需照搬其分辨率。上游归一化脚本与桌面端脚底常量也不宜混用，应检查最终导出后的实际位置。

移动实现还支持按帧位移曲线与每圈步幅，使动画播放进度和窗口位置共用进度依据。该方法可用于改善脚底滑动；具体曲线仍要针对我们自己的步态测量。

## Robin-pet 当前差异

| 项目 | 当前情况 | 优化方向 |
| --- | --- | --- |
| 动作闭环 | 随附待机、招呼保留真实帧往返，其余新动作正向播放 | 新素材自然收势，完整动作正向播放；保留旧包兼容 |
| 衔接 | 手动响应立即开始，约 120ms 整帧混合；不同片段姿态仍有差异 | 统一入口/出口姿态；混合仅作辅助，避免双影 |
| 抠像 | OpenCV HSV、边缘处理与可选绿色眼睛保护 | 增加人工精修 alpha 的输入路线，检查头发、手指、眼睛和饰品 |
| 几何 | 固定画布和全动作联合边界，依赖输入视频本来就大小一致 | 按各段标准站姿估计固定缩放和平移，统一脚底锚点 |
| 移动 | 只在 walk 阶段位移，向左匀速，速度为角色尺寸的固定比例 | 独立左右步态、每圈步幅和可选逐帧位移曲线 |
| 素材组织 | PNG 帧包和 manifest，按需预取与约 96 MiB 的渲染缓存 | 先测量内存与启动时间，再评估按动作缓存或透明 WebM |

当前通用制作入口为 `tools/prepare_video2.py`，实现为 `tools/prepare_assets.py`；播放在 `video_motion.py`，桌面位移在 `pet.py`。本版本已按上文更新播放器及动作调度，后文标注“计划”的项目仍为后续方案。

## 适配 5 秒视频的制作要求（计划）

每个视频只承载一个动作，使用同一张正面定妆图与同一套角色比例、镜头、光照和地面高度。三视图用于约束侧面、背面的一致性，不要求每段动作都转一圈。背景采用适合角色配色的纯色；人物有绿色眼睛或服饰时，应精修遮罩或使用支持透明输出的流程。

优先准备以下素材：

| 素材 | 5 秒内的内容 | 入口与出口 |
| --- | --- | --- |
| 待机 | 慢呼吸、一次自然眨眼、轻微手指和发梢运动 | 同一放松正面站姿，呼吸相位连续 |
| 招呼 | 0–0.3 秒开始抬手，0.3–3.5 秒轻摆手并微笑，3.5–5 秒自然放下 | 统一正面站姿；开头不保留长时间静止 |
| 转向左 / 转回正面 | 各一段，重心带动脚、腰、肩、头自然转向 | 正面站姿 ↔ 统一左侧站姿 |
| 向左走路 | 原地完整步态，手臂自然反向摆动，衣物有跟随 | 相同侧向步态相位，无停步收尾 |
| 向右走路及对应转向 | 与左向同样拆分，保留饰品和服装方向 | 对应的右侧姿态与步态相位 |

转向、起步、循环走路和停步回正面可继续拆段；不要把转身、走路、回正面都挤进同一段 5 秒视频。步态中脚部应有明确支撑与摆动；人物整体在源视频中保持居中。不能简单要求两脚全程钉在原点，那会妨碍迈步。

每段导出后必须检查，提示词中的“首尾一致”并不保证模型实际做到。不合格片段应调整或重做；单纯增加帧率、倒放或混合无法修复肢体结构错误和动作逻辑。

## 实施顺序与验收（计划）

1. 先完成待机、招呼、左侧走路三类试片，并审查源视频。保留当前随附帧包作为可运行基线。
2. 扩展制作工具，支持已精修的透明素材、逐片段固定几何校准、正向循环和入口/出口元数据。缩放和平移对整段固定，避免逐帧追踪边界引入抖动。
3. 扩展动作衔接与步态位移：统一播放进度，记录每圈步幅和方向，必要时引入逐帧曲线。停步与打断都有匹配的收势素材；点击即时反馈与身体完整收势分别设计。
4. 测量 PNG 帧包的下载体积、加载时间、内存和不同 DPI 清晰度。随后用少量片段验证 VP9 alpha 播放，再决定是否增加 WebM 后端。

验收至少覆盖：正常速度与逐帧检查、深浅两种底色下的透明边缘、连续循环和跨动作连接、手部连续运动、脚底支撑与桌面位移同步、快速重复点击、拖动打断、待机恢复，以及 100%/150%/200% 显示缩放。检查启动和切换时不存在绿底、黑底、空帧或明显重影。新素材通过验收后再替换默认帧包。
